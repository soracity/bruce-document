### LayoutSpanは100等分で扱う

横方向の幅比率は**100等分**を基本単位とする。

```html
<app-layout-item>
  <app-textbox [appLayoutSpan]="70" ... />
  <app-date [appLayoutSpan]="30" ... />
</app-layout-item>
```

上記は70:30の比率を表す。

原則として、同一`LayoutItem`内で明示的に`appLayoutSpan`を指定する場合、兄弟要素のspan合計を**100**とする。

例：

- `50 + 50 = 100`
- `70 + 30 = 100`
- `60 + 40 = 100`
- `20 + 30 + 50 = 100`

`appLayoutSpan`の値は**CSSの`width: n%`そのものではない**。LayoutItemが持つgap等を除いた利用可能領域を、指定されたspan比率に従って分配するための**重み**として扱う。

したがって、`70 + 30 + gap`をそのまま`70% + 30% + gap`として実装し、100%を超過させる実装は行わない。

### 明示指定と未指定を混在させない

同一`LayoutItem`内では、次のどちらかに統一する。

1. 全兄弟で`appLayoutSpan`を省略し、均等割りとする。
2. 全兄弟で`appLayoutSpan`を明示し、合計100の比率を指定する。

以下のような混在は採用しない。

```html
<app-layout-item>
  <app-textbox [appLayoutSpan]="70" ... />
  <app-date ... />
</app-layout-item>
```

未指定値を「残り全部」「1」「自動値」等と解釈する余地をなくし、人間とAIの双方にとって実装規則を明確にするためである。

##### 基本原則

LayoutManagerはComponentに**どれだけの領域を与えるか**を決める。共通Componentは**与えられた領域の中でどう描画するか**を決める。画面ComponentはCSSで幅を直接決めない。

| 対象 | 責務 |
|---|---|
| LayoutItem | 子Componentへ割り当てる横方向の領域を管理する |
| LayoutSpan | LayoutItem内における子Componentの幅比率を指定する |
| Textbox / Date / Radio / Button等 | LayoutManagerから与えられた領域内で自身を描画する |
| 画面Component | 画面上意味のある比率だけをLayoutSpanで指定する。CSSのwidth系classを直接指定しない |

##### Component内部の100%幅は許容する

画面側から共通Componentへ`w-full`等を注入して幅を決めない。

```html
<app-textbox classInput="w-full" ... />
```

上記のような指定は廃止対象とする。

一方、Textbox内部のinputが次のように自身へ割り当てられた領域を100%使用することは許容する。

```css

  width: 100%;
}
```

この100%は画面全体に対する100%ではなく、**LayoutManagerからTextboxへ割り当てられた領域の100%**である。

Buttonについても、LayoutManagerは`app-button`ホストへ割り当てる領域までを担当し、内部のネイティブ`button`を全面幅にするか内容幅にするかはButtonComponentのデザイン責務とする。

画面Componentから`w-full`等を注入して決定しない。

##### AI実装ルール

AIが画面を実装する場合も次を遵守する。

- 通常は`appLayoutSpan`を省略して均等割りを使用する。
- 比率変更が必要な場合のみ`appLayoutSpan`を使用する。
- `appLayoutSpan`を使う場合は同一`LayoutItem`内の全兄弟へ明示し、合計100とする。
- `appLayoutSpan`をCSSの`width:%`へ単純変換しない。
- 画面Componentで`w-*`等のwidth系CSSを直接使って配置を調整しない。

### 2026-10-18：合計100・指定混在禁止の検査方式（当時の比較案・後にBを承認）

### 2026-10-18：数値リテラルのみ許可（承認済み）

- **工程ID**：2.2.4
- **ユーザー決定①**：span違反の検査方式として **B：静的検査** を採用する。
- **ユーザー決定②**：`appLayoutSpan` は **数値リテラルによる指定のみ許可**する。
- **許可例**：`[appLayoutSpan]="70"`、`[appLayoutSpan]="30"`。指定値は正の有限数とし、同一LayoutItemの直接子で明示する場合は全てに指定し、合計100とする。全未指定は均等割り。
- **禁止例**：`[appLayoutSpan]="dto.width"`（変数）、`[appLayoutSpan]="100 - width"`（計算式）、`appLayoutSpan="70"`（文字列属性）。数値ではない値や0・負数も既存規則に反する。
- **決定理由**：画面HTMLを見れば幅比率が明らかで、人間による解析・保守と静的検査が容易。
- **設計上の区別**：静的検査方式と数値リテラル限定は**承認済み**。検査器の実装方式、`@if`／`@for`といった構造上の扱い、ビルド経路・実装完了・テストは**未決または未着手**。
- **現行コードとの差**：`LayoutSpanDirective`は入力が不正な場合`flex-grow=1`へ補正するが、これは検査仕様に沿うFail Fastではない。ソースはまだ変更しない。
- **次の議題**：`<app-layout-item>`の直接子に`@if`／`@for`を置く場合の静的検査の扱いを決める。

### 2026-10-18：条件付き非表示時の比率維持による自動再配分（承認済み）

- **工程ID**：2.2.4（関連：2.2.5、2.4）
- **ユーザー承認事項**：`@if`によりLayoutItem内の項目が非表示になった場合、表示中の項目だけで、残りの`appLayoutSpan`の**相対比率を維持して利用可能幅を自動再配分する**。
- **例**：`50 : 30 : 20`の3項目のうち`20`の項目が非表示なら、残り2項目は`50/80 × 100 = 62.5%`と`30/80 × 100 = 37.5%`。残り1項目なら100%を使用する。いずれもgapを除いた領域を配分する。
- **意図**：条件付き非表示で表示中のspan合計が100未満となることは、指定ミスではなく正常なレイアウト動作として扱う。画面側で動的span計算を書かず、Layoutの責務として再配分する。
- **既承認仕様の維持**：`[appLayoutSpan]="50"`等の数値リテラル指定のみ許可。元の指定が不正なケース（例：条件が全て成立しても`70 + 20 = 90`のまま）は静的検査で発見する方針を維持する。
- **重要な区別**：以前の「LayoutItem直下の`@if`／`@for`を一律禁止する方針A」は、この再配分要件に対してそのまま適用しない。`@if`を扱える設計を検討するが、**直接子の許可条件・`@else`・複数条件の組合せ・`@for`の扱い・全パターンでの静的検査方式・ビルド組込み**はまだ承認されていない。
- **実装・検証状態**：設計方針のみ承認。実装はPhase 5、テストは後続工程。現時点で動作保証や検査器の完成を意味しない。
- **次の議題**：指定値の誤りと条件付き非表示を区別できる静的検査規則（`@if`／`@else`等の分岐評価）の具体化。

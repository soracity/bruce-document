#### 承認済みIssue：幅の責務

> 状態：**設計承認済み**  
> 承認日：2026-10-16

##### 基本原則

LayoutManagerはComponentに**どれだけの領域を与えるか**を決める。共通Componentは**与えられた領域の中でどう描画するか**を決める。画面ComponentはCSSで幅を直接決めない。

| 対象 | 責務 |
|---|---|
| LayoutItem | 子Componentへ割り当てる横方向の領域を管理する |
| LayoutSpan | LayoutItem内における子Componentの幅比率を指定する |
| Textbox / Date / Radio / Button等 | LayoutManagerから与えられた領域内で自身を描画する |
| 画面Component | 画面上意味のある比率だけをLayoutSpanで指定する。CSSのwidth系classを直接指定しない |

##### LayoutSpanは100等分で扱う

横方向の幅比率は**100等分**を基本単位とする。

```html
<app-layout-item>
  <app-textbox [appLayoutSpan]="70" ... />
  <app-date [appLayoutSpan]="30" ... />
</app-layout-item>
```

上記は70:30の比率を表す。

原則として、同一`LayoutItem`内で明示的に`appLayoutSpan`を指定する場合、兄弟要素のspan合計を**100**とする。

例：

- `50 + 50 = 100`
- `70 + 30 = 100`
- `60 + 40 = 100`
- `20 + 30 + 50 = 100`

`appLayoutSpan`の値は**CSSの`width: n%`そのものではない**。LayoutItemが持つgap等を除いた利用可能領域を、指定されたspan比率に従って分配するための**重み**として扱う。

したがって、`70 + 30 + gap`をそのまま`70% + 30% + gap`として実装し、100%を超過させる実装は行わない。

##### span未指定時は均等割り（2.2.1の原則）

同一`LayoutItem`内ですべての兄弟が`appLayoutSpan`を省略した場合は均等幅となる。2項目なら50:50、3項目なら各約33.3%。正常なHTML例と詳細は[2.2.1](#221-layoutitem未指定兄弟の均等割りを決定)へ集約した。これは明示指定時の合計100規則とは別のケースである。

##### 明示指定と未指定を混在させない

同一`LayoutItem`内では、次のどちらかに統一する。

1. 全兄弟で`appLayoutSpan`を省略し、均等割りとする。
2. 全兄弟で`appLayoutSpan`を明示し、合計100の比率を指定する。

以下のような混在は採用しない。

```html
<app-layout-item>
  <app-textbox [appLayoutSpan]="70" ... />
  <app-date ... />
</app-layout-item>
```

未指定値を「残り全部」「1」「自動値」等と解釈する余地をなくし、人間とAIの双方にとって実装規則を明確にするためである。

##### Component内部の100%幅は許容する

画面側から共通Componentへ`w-full`等を注入して幅を決めない。

```html
<app-textbox classInput="w-full" ... />
```

上記のような指定は廃止対象とする。

一方、Textbox内部のinputが次のように自身へ割り当てられた領域を100%使用することは許容する。

```css
input {
  width: 100%;
}
```

この100%は画面全体に対する100%ではなく、**LayoutManagerからTextboxへ割り当てられた領域の100%**である。

##### Radio・Button等の内部幅

Radio内部の選択肢を等幅にする等の処理はRadioComponent自身の内部レイアウト責務とする。

Buttonについても、LayoutManagerは`app-button`ホストへ割り当てる領域までを担当し、内部のネイティブ`button`を全面幅にするか内容幅にするかはButtonComponentのデザイン責務とする。

画面Componentから`w-full`等を注入して決定しない。

##### AI実装ルール

AIが画面を実装する場合も次を遵守する。

- 通常は`appLayoutSpan`を省略して均等割りを使用する。
- 比率変更が必要な場合のみ`appLayoutSpan`を使用する。
- `appLayoutSpan`を使う場合は同一`LayoutItem`内の全兄弟へ明示し、合計100とする。
- `appLayoutSpan`をCSSの`width:%`へ単純変換しない。
- 画面Componentで`w-*`等のwidth系CSSを直接使って配置を調整しない。

```html
</app-layout-item>
```

### 2026-10-18：条件付き非表示時の比率維持による自動再配分（承認済み）

### 2026-10-19：単独 `@if` の静的検査規則（ユーザー承認済み）

- **工程ID**：2.2.4／関連：2.2.5。
- **承認状態**：設計承認済み（ユーザーが本会話で明示承認）。**実装状態**：未着手。**検証状態**：未検証。2.2.4小区分全体は進行中のまま。
- **承認した規則**：`<app-layout-item>`直下に単独の`@if`を許可し、`@if`が成立して条件付きの子項目も表示される構成を基準に、全兄弟の`appLayoutSpan`が明示され合計100であることを**静的検査**する。全省略の場合は既承認の均等割り規則を適用する。明示と省略の混在は認めない。
- **非表示時の動作**：単独`@if`が不成立となり、項目が消えた場合は、表示中の子項目の`appLayoutSpan`の**相対比率**を保ち、gapを除いた利用可能幅で自動再配分する。画面で動的spanを計算しない。
- **不正指定の扱い**：`@if`が成立した元の構成で合計100にならない場合（例：70+20=90）は、非表示時に幅を再配分できても**設計違反として静的検査で検出**する。数値リテラル以外の指定は従来どおり禁止。
- **今回の承認範囲**：下記例のように、同一LayoutItemに通常の兄弟要素と**1つの`@if`（`@else`なし）による条件付き子要素**がある構成についての規則を確定したもの。複数の条件付き子・`@else`・独立した複数`@if`・`@for`・表示要素が0となるケース等へ、検査方式を独断で一般化しない。
- **決定理由**：HTML中の元の比率指定ミスを検出しつつ、正常な条件付き非表示を許容し、Layout側の責務として比率再配分を行うため。

```html
<app-layout-item>
  <app-textbox [appLayoutSpan]="50" />
  <app-date [appLayoutSpan]="30" />
  @if (showMemo) {
    <app-textbox [appLayoutSpan]="20" />
  }
</app-layout-item>
```

- `showMemo=true`：50+30+20=100（静的検査の基準となる構成）。
- `showMemo=false`：残り50:30を62.5:37.5に再配分（正常）。
- **当時の未決・後続で解決**：記録時点では`@if/@else`の排他的分岐が未決だったが、2026-10-19の次節で承認済み。複数`@if`の組合せ、`@for`の扱い、検査ツールの実装・ビルドへの組込みと検出時の失敗条件は引き続き未決。
- **関連証跡**：2026-10-18の方式B・数値リテラル限定・非表示再配分の承認記録（本ファイル直前の節）、本会話における2026-10-19のユーザー承認。

### 2026-10-19：単一 `@if/@else` の排他的分岐ごとの静的検査（ユーザー承認済み）

- **工程ID**：2.2.4／関連：2.2.5。
- **承認状態と根拠**：設計承認済み。2026-10-19の本会話で、具体例を示した「`@if/@else`の各分岐でspan合計100を静的検査する方式」に対してユーザーが「OK」と承認。**実装**：未着手／**検証**：未検証。工程2.2.4全体は進行中。
- **対象と検査規則**：`<app-layout-item>`内に通常の兄弟要素と**単一の`@if ... @else`構造**があり、それぞれの分岐に代替の子Componentがある場合、`@if`側を選んだ構成と`@else`側を選んだ構成を**別々に静的評価**する。各構成で、全子Componentへのspan明示・数値リテラル限定・**span合計100**の既承認規則を満たす必要がある（全省略の均等割りは既承認規則に従う）。
- **排他性**：`@if`側と`@else`側のspanを**同時に合算しない**。通常の兄弟要素は両方の構成に含める。
- **例**：共通兄弟の50+30に、`@if`側20または`@else`側20が加わり、どちらも100なので正常。もし`@else`側だけ10なら50+30+10=90で静的検査エラーとする。
- **決定理由**：排他的な分岐で実際には同時表示しない要素を合算せず、各表示構成に存在する指定ミスを確実に見つけるため。画面がspanを再計算して帳尻を合わせる方式は採らない。
- **承認範囲の境界**：この具体例のような**単一の`@if/@else`の排他的代替**に限定する。独立した複数`@if`、ネストした`@if`、`@else if`、`@for`、分岐が複数要素・空要素を返すケース、ゼロ項目時の扱い、ビルドへの組込み方式はこの承認から自動的には導かない。
- **以前の承認との関係**：`@else`なしの単独`@if`では、全表示時合計100・一部非表示時相対比率再配分の既承認を維持する。今回の規則は**代替表示**の場合を追加するものであり、単独`@if`の非表示状態に合計100を要求し直すものではない。

```html
<app-layout-item>
  <app-textbox [appLayoutSpan]="50" />
  <app-date [appLayoutSpan]="30" />
  @if (showMemo) {
    <app-textbox [appLayoutSpan]="20" />
  } @else {
    <app-button [appLayoutSpan]="20" />
  }
</app-layout-item>
```

- **次の議題（記録当時未承認）**：独立した複数`@if`の組合せと基準となるspan合計の検査方式。その後、`@for`とビルド組込み・エラー処理を検討する。後続で排他的条件の`@else if`記法を承認したが、真に独立した複数`@if`の検査基準はまだ未決。

### 2026-10-19：排他的条件は `@if/@else if/@else` を用いる（ユーザー承認済み）

- **工程ID**：2.2.4／関連：2.2.5、2.8.1（AI実装制約）。
- **承認状態と根拠**：設計承認済み。排他的な複数条件は別々の`@if`より`@if/@else if/@else`を推奨する比較・規則を提示し、ユーザーが2026-10-19に「@else ifで承認します」と明示した。**実装**：未着手／**検証**：未検証。工程2.2.4は進行中。

- **末尾に`@else`がない場合**：いずれの条件にも該当せず条件付き要素が0個になる場合、共通兄弟が残っていれば、そのspanによる相対比率維持再配分を適用する（例：共通要素のspan50が残れば利用可能幅を100%使用）。これは条件不成立の正常動作であり、仮想の空分岐にspan合計100を要求する趣旨ではない。**LayoutItemの子が完全に0個になるケースは引き続き未決**。
- **決定理由**：複数の独立`@if`から条件の排他性を高度な式解析で推測する必要をなくし、AI生成HTMLの見通し・人間のレビュー・静的検査を単純化するため。
- **検出可能性に関する制約**：コードが排他的な条件なのに独立`@if`を利用したかどうかは、条件式の意味を評価しない単純な構文検査だけでは一般に判定できない。**書き方の禁止は設計・AI実装規則として承認**するが、静的検査器が意味上の排他性を完全に自動検出することまでは承認・実装済みと扱わない。
- **承認範囲の境界**：下記のように共通兄弟1項目＋一つの排他的な`@if / @else if`連鎖で各分岐が1項目を表示する例を基準とする。ネスト、任意段数・複数要素を持つ分岐、独立した複数`@if`の組合せ、`@for`、ゼロ子項目、静的検査器の実装方法・ビルド統合は**未決**であり、今回の承認から一律に完成とはしない。

```html
<app-layout-item>

    <app-textbox [appLayoutSpan]="50" />
  }
</app-layout-item>
```

- `mode='DATE'`：50+50=100（検査対象）。
- `mode='MEMO'`：50+50=100（検査対象）。
- その他：共通要素50が残り、比率維持再配分で100%利用する。

- **未完了事項・引継ぎ**：2.2.4で検査仕様を決定した後にPhase 5で実装、Phase 7で条件付き非表示と通常構成をテストする。未変更のコードを承認済み実装と扱わない。
- **次の作業**：現行flex-grow／basis-0と規則の対応を確認

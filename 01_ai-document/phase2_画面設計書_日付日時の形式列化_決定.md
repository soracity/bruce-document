# Phase2 画面設計書 日付・日時の形式列化 決定

> 状態：設計承認済み  
> 承認日：2026-10-16

## 決定内容

画面設計書の `型` 列では、TypeScript上の型を表す。

`日付` および `日時` はTypeScript上ではいずれも `string` として扱うため、`文字列` と型として区別しない。

そのため、画面設計書では `日付`・`日時` を `型` 列ではなく `形式` 列で表現する。

概念は以下とする。

```text
文字列
  ├─ 形式なし
  ├─ 日付
  └─ 日時
```

例：

```text
日付項目
型   = 文字列
形式 = 日付

日時項目
型   = 文字列
形式 = 日時
```

生成されるTypeScript型はいずれも `string` とする。

```ts
FormControl<string>
```

## 型列

画面設計書の `型` 列で使用する種別は以下とする。

```text
文字列
数値
真偽
Enum
```

`日付`・`日時` は型列から削除する。

## 形式列

画面設計書の `形式` 列では以下を扱う。

```text
-
半角数字
半角英数字
半角英数字記号
正規表現
日付
日時
```

`日付`・`日時` は `型=文字列` と組み合わせる。

## 多言語対応

`形式=日付` / `形式=日時` は、特定の国・言語向けの固定表示フォーマットを意味しない。

画面設計書には `yyyy/MM/dd` や `MM/dd/yyyy` などを固定値として埋め込まず、日付・日時という意味のみを指定する。

内部値は言語・地域に依存しない統一形式で保持し、画面表示時にロケールに応じた形式へ変換する。

例：

```text
内部値（日付）
2026-10-16

内部値（日時）
2026-10-16T13:30:00
```

表示形式はロケールに応じて決定する。

```text
ja-JP : 2026/10/16
en-US : 10/16/2026
en-GB : 16/10/2026
```

責務は以下のように分離する。

```text
型
→ TypeScript上のデータ型

形式
→ 日付・日時という値の意味

表示形式
→ 言語・地域（ロケール）に応じて決定
```

## 今回のACG改修範囲

今回の改修で以下を実施する。

- 型から `日付` / `日時` を削除する
- 共通 `TypeScriptTypeEnum` から `DATE` / `DATE_TIME` を削除する
- UI DTO生成側の `DATE` / `DATE_TIME` 分岐を削除する
- DAO生成など、`DATE` / `DATE_TIME` を直接参照している箇所を `STRING` 前提へ整理する
- 形式に `日付` / `日時` を追加する

## 未決事項

以下は別途設計する。

- `形式=日付` の具体的な入力・Validation仕様
- `形式=日時` の具体的な入力・Validation仕様
- `文字種` 列との組み合わせルール

本決定は、画面設計書において `日付`・`日時` を `型` ではなく `形式` として扱い、今回のACG改修対象に含めることを対象とする。

#### （５）型
画面設計書で使用できる型は以下とする。

- 文字列：`string`
- 数値：`number`
- 真偽：`boolean`
- Enum：既存の自動生成Enum型

日付・日時は型ではなく、文字列型の`形式`として指定する。

```text
型=文字列 / 文字種=- / 形式=日付
型=文字列 / 文字種=- / 形式=日時
```

`形式=日付`はカレンダー日付として扱う必要がある場合に使用する。タイムゾーン変換対象となる実時刻・イベントは`形式=日時`を基本とする。

#### （６）Enum型
`型=Enum`の場合は`Enum型`を必須指定する。

`Enum型`には、既存の列挙型設計書から自動生成されるEnumの物理名を指定する。

例：

- 試合タイプ：`AppCodeMatchTypeEnum`
- 試合設定：`AppCodeMatchSettingEnum`
- セット設定：`AppCodeNumberOfSetsEnum`
- ゲーム確定：`AppCodeGameFinalEnum`
- 状態：`AppCodeMatchStatusEnum`
- タイブレークモード：`AppCodeTieBreakEnum`
- コートサイド：`AppCodeCourtSideEnum`

`型!=Enum`の場合は`Enum型=-`とする。

ACGは`型=Enum`の場合、指定されたEnum型をimportし、FormControlの型として使用する。Enumそのものは画面設計書から新規生成しない。

Enum型FormControlはコード値文字列ではなくEnumオブジェクトを保持する。

#### （７）文字種
通常の文字列項目は、文字種として以下のいずれかを指定する。

- ASCII
- Unicode

ただし、Validationなしの文字列、`形式=日付`、`形式=日時`の場合は`文字種=-`とする。

```text
型=文字列 / 文字種=- / 形式=-
型=文字列 / 文字種=- / 形式=日付
型=文字列 / 文字種=- / 形式=日時
```

文字列以外の型は`文字種=-`とする。

#### （８）Validation

##### Validationなし文字列
文字列項目にValidationを行わない場合は以下の組み合わせとする。

```text
型=文字列 / 文字種=- / 形式=-
```

この場合、必須・必須(真偽)・文字数・数値範囲・正規表現はすべて`-`とし、ACGはValidationを生成しない。

プログラム側で生成・設定する値など、画面入力値としてValidationする必要がない文字列に使用する。

##### Unicode文字列
指定可能なValidationは以下のみとする。

- 必須
- 文字数(最小/最大)

`Unicode`はUnicode専用Validatorを生成する指定ではない。ASCII限定チェックを行わず、Unicode文字を許可することを表す。

`Unicode`指定時は、形式・必須(真偽)・数値(最小/最大)・正規表現を指定してはならない。

##### ASCII文字列
指定可能な`形式`は以下の4種類とする。

```text
半角数字
半角英数字
半角英数字記号
正規表現
```

`文字種=ASCII / 形式=-`は使用しない。

ASCII文字列では、必須・文字数(最小/最大)を指定可能とする。

`半角英数字記号`は半角スペースを含む印字可能ASCII文字を許可する。`形式=正規表現`の場合のみ、`正規表現`列を必須指定する。

##### 日付・日時
日付・日時は以下の組み合わせとする。

```text
型=文字列 / 文字種=- / 形式=日付
型=文字列 / 文字種=- / 形式=日時
```

指定可能なValidationは`必須`のみとする。

日付・日時の入力形式は日付・日時入力コンポーネント側で保証するため、ACGは日付・日時専用の形式ValidatorをFormControlへ生成しない。

日付・日時の場合、文字数・数値範囲・正規表現は指定しない。

`形式=日時`の内部値はUTCのISO 8601を基本とする。

例：

```text
2026-10-16T06:24:00.000Z
```

##### 数値
指定可能なValidationは以下とする。

- 必須
- 数値(最小/最大)

文字種・形式・必須(真偽)・文字数・正規表現は指定しない。

##### 真偽
指定可能なValidationは`必須(真偽)`のみとする。

文字種・形式・必須・文字数・数値範囲・正規表現は指定しない。

##### Enum
指定可能なValidationは`必須`のみとする。

文字種・形式・必須(真偽)・文字数・数値範囲・正規表現は指定しない。

Enum値として許可される値の定義は、参照する列挙型設計書および自動生成Enumを正とする。画面設計書側で候補値をValidationとして重複定義しない。

#### （９）Validation指定値
##### 必須
型に応じて必須チェックを分ける。

```text
文字列 + 必須=〇
→ trim後の空文字もNGとする必須チェック

数値 + 必須=〇
→ Validators.required 相当

Enum + 必須=〇
→ Validators.required 相当

真偽 + 必須(真偽)=〇
→ Validators.requiredTrue 相当
```

文字列では以下をNGとする。

```text
null
""
" "
"   "
```

具体的な文字列必須Validatorのクラス名・メソッド名は実装設計で決定する。Angular標準`Validators.required`だけでスペースのみを許可しない仕様を満たしたものとして扱わない。

##### 文字数(最小/最大)・数値(最小/最大)
範囲指定は以下を許可する。

```text
10
3/10
-/10
3/-
10/10
-
```

単一値`10`は`0/10`と同義とする。

文字数で`10`を指定した場合は`Validators.maxLength(10)`を生成し、冗長な`Validators.minLength(0)`は生成しない。

数値で`10`を指定した場合は`Validators.min(0)`と`Validators.max(10)`を生成する。

`10/10`は最小値と最大値が同じ指定として扱う。

#### （１０）デフォルト
`デフォルト=-`はデフォルト未指定を表す。FormControl初期値は以下とする。

| 型・形式 | デフォルト | FormControl初期値 |
|---|---|---|
| 文字列 | `-` | `''` |
| 文字列 | 任意文字列 | 指定文字列 |
| 数値 | `-` | `null` |
| 数値 | 数値 | 指定数値 |
| 真偽 | `-` | `false` |
| 真偽 | `true` / `false` | 指定値 |
| Enum | `-` | `null` |
| Enum | コード値 | `Enum型.toEnum('コード値')` |
| 文字列＋日付 | `-` | `''` |
| 文字列＋日付 | `SYSTEM_DATE` | `AppDateUtil.getSysDateIso8601()` |
| 文字列＋日時 | `-` | `''` |
| 文字列＋日時 | `SYSTEM_DATETIME` | `AppDateUtil.getSysDateTimeUtcIso8601()` |

`必須=〇`であっても、ACGは必須であることを理由にデフォルト値を推測・補完しない。

日付・日時の予約語は対応する形式と1対1で使用する。

```text
形式=日付 + SYSTEM_DATE
→ OK

形式=日時 + SYSTEM_DATETIME
→ OK

形式=日付 + SYSTEM_DATETIME
→ Exception

形式=日時 + SYSTEM_DATE
→ Exception

日付・日時以外 + SYSTEM_DATE / SYSTEM_DATETIME
→ Exception
```

`createDateTime`、`updateDateTime`、`deleteDateTime`等を物理名や用途だけで特別扱いしない。初期値は各行の`デフォルト`列に従う。

#### （１１）ACG Validation・仕様チェック
ACGはDTO生成前に、16列の指定内容と型別ルールを検証する。

本設計書のルールに反する指定が存在する場合、ACGは値を補正・無視して生成を継続せず、Exceptionを発生させてコード生成を停止する。

例：

- `型=文字列 / 文字種=ASCII / 形式=-` → Exception
- `型=文字列 / 文字種=Unicode / 形式=半角数字` → Exception
- `型=文字列 / 文字種=- / 形式=-`でValidation指定あり → Exception
- `形式=日付`または`形式=日時`で文字種指定あり → Exception
- `型=真偽 / 必須=〇` → Exception
- `型=数値 / 文字数(最小/最大)=1/3` → Exception
- `形式=正規表現`で正規表現未指定 → Exception
- `形式!=正規表現`で正規表現指定あり → Exception
- `型=Enum / Enum型=-` → Exception
- `型!=Enum`でEnum型指定あり → Exception
- `型=Enum`で禁止Validation指定あり → Exception
- 最小値が最大値を上回る指定 → Exception
- `SYSTEM_DATE` / `SYSTEM_DATETIME`と形式の組み合わせ不一致 → Exception

Exceptionメッセージには、少なくとも物理名・型・Enum型・文字種・不正な指定項目・不正理由を含める。

ACGは不正な設計書を推測して補正しない。Fail Fastで停止する。

##### ACG内部モデル
- DTO項目モデルに`Enum型`を保持する。
- DTO項目モデルに`文字種（ASCII / Unicode / -）`を保持する。
- DTO項目の型として`Enum`を表現する。
- 画面DTOの型は文字列・数値・真偽・Enumとして扱い、日付・日時を型として扱わない。
- 共通のTypeScript型Enumは`TypeScriptTypeEnum`とし、`DATE`・`DATE_TIME`を削除して`ENUM`を追加する。

##### Component DTO生成
- UI Form DTOは通常のclassとして生成し、`FormGroup`をプロパティとして保持する。
- UI Form DTOは`@Injectable()`とし、`providedIn: 'root'`を生成しない。
- 画面側ではComponentの`providers`へUI Form DTOを登録し、`inject()`で取得する。
- `型=Enum`では`FormControl<指定Enum型>`としてEnumオブジェクトを保持する。
- Enum型を`@approot/app/brf9000/brf9011-enum/code/`配下からimportする。
- Enumクラス名から末尾`Enum`を除去し、kebab-caseへ変換してファイル名を決定する。末尾`Enum`がない場合は推測せずFail Fastとする。
- 同一Enum型のimportを重複生成しない。
- Enumデフォルト値のコードは`Enum型.toEnum('コード値')`で解決する。
- `デフォルト=-`の場合は型別の既定初期値を使用する。
- `SYSTEM_DATE` / `SYSTEM_DATETIME`は固定文字列として設定せず、対応する`AppDateUtil`呼び出しへ変換する。

##### Validation生成
- `型=文字列 / 文字種=- / 形式=-`ではValidationを生成しない。
- ASCII文字列では指定形式に応じたパターンValidationを生成する。
- Unicode文字列ではUnicode専用パターンValidationを生成しない。
- `形式=正規表現`の場合のみ、`正規表現`列からパターンValidationを生成する。
- `形式=日付` / `形式=日時`では日付・日時専用の形式Validatorを生成しない。
- 文字列の`必須=〇`ではtrim後の空文字もNGとする必須チェックを生成する。
- 数値・Enumの`必須=〇`では`Validators.required`相当を生成する。
- 真偽の`必須(真偽)=〇`では`Validators.requiredTrue`相当を生成する。
- 文字数・数値範囲は指定された側だけValidatorを生成する。

##### 仕様チェック（Fail Fast）
DTOコード生成前に、型・Enum型・文字種・形式・Validation・デフォルトの組み合わせを検証する。

不正指定をACG側で補正・無視して生成を続行しない。

#### （１３）Enum FormControlの値取得・境界変換
Component DTO（UI Form DTO）のEnum項目は、FormControl内部にEnumオブジェクトを保持する。

例：

```ts
FormControl<AppCodeMatchTypeEnum>
```

この場合、FormControlから取得する値は以下の関係となる。

```text
matchType
  ↓ FormControl
matchType.value
  ↓ AppCodeMatchTypeEnum
matchType.value.value
  ↓ string（例："0" / "1"）
matchType.value.name
  ↓ string（例："SINGLES" / "DOUBLES"）
```

Application DTO等が文字列コードを要求する場合は、画面ComponentのUI/Application境界でEnumの`value`を渡す。

```ts
matchType: this.dto.formGroup.controls.matchType.value?.value
```

nullableでないことが型定義上保証されている場合は以下でもよい。

```ts
matchType: this.dto.formGroup.controls.matchType.value.value
```

Application Response等の文字列コードをEnum型FormControlへ設定する場合は、対象Enumの`toEnum()`でEnumオブジェクトへ変換してから`patchValue` / `setValue`する。

```text
Application DTO / Response
string（例："0"）
  ↓ toEnum()
AppCodeMatchTypeEnum.SINGLES
  ↓ patchValue / setValue
FormControl<AppCodeMatchTypeEnum>
```

FormControlがすでにEnum型を保持しているUI内部では、値取得のたびに`toEnum()`を呼び出さない。

UI Form DTOとApplication DTO間の変換は画面Componentで明示的に行い、専用Mapper / Converter / Assemblerは作成しない。抽象化が必要に見える場合は、設計確認を行ってから変更する。

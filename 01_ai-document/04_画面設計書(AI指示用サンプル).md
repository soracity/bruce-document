#### （５）型
- 文字列：string
- 数値：number
- 日付：string
- 真偽：boolean
- Enum：既存の自動生成Enum型をComponent DTO（UI Form DTO）のFormControl型として指定可能

Enumを指定した場合、ACGはEnumそのものを画面設計書から新規生成しない。既存の自動生成Enumを参照・importしてComponent DTOのFormControl型として使用する。

#### （６）Enum型
`型=Enum`の場合は`Enum型`を必須指定する。

`Enum型`には、既存の列挙型設計書から自動生成されるEnumの物理名を指定する。

例：

- 試合タイプ：`AppCodeMatchTypeEnum`
- 試合設定：`AppCodeMatchSettingEnum`
- セット設定：`AppCodeNumberOfSetsEnum`
- ゲーム確定：`AppCodeGameFinalEnum`
- 状態：`AppCodeMatchStatusEnum`
- タイブレークモード：`AppCodeTieBreakEnum`
- コートサイド：`AppCodeCourtSideEnum`

`型!=Enum`の場合は`Enum型=-`とする。

ACGは`型=Enum`の場合、指定されたEnum型をimportし、FormControlの型として使用する。

Enum型自体の生成責務は列挙型設計書側にあり、画面設計書から同一Enumを重複生成しない。

#### （７）文字種
文字種は文字列型の場合のみ指定する。

- ASCII
- Unicode

文字列以外の型は `-` とする。

#### （８）Validation

##### 文字列

###### Unicode
指定可能なValidationは以下のみとする。

- 必須
- 文字数(最小/最大)

`Unicode`はUnicode専用Validatorを生成する指定ではない。ASCII限定の文字種チェックを行わず、Unicode文字の入力を許可することを表す。

`Unicode`指定時は以下を指定してはならない。

- 形式
- 必須(真偽)
- 数値(最小/最大)
- 正規表現

###### ASCII
指定可能なValidationは以下とする。

- 形式
  - 半角数字
  - 半角英数字
  - 半角英数字記号
  - 正規表現
- 必須
- 文字数(最小/最大)

`ASCII`指定時は以下を指定してはならない。

- 必須(真偽)
- 数値(最小/最大)

`形式=正規表現`を指定する場合のみ、`正規表現`列にパターンを指定する。

##### 真偽
指定可能なValidationは以下のみとする。

- 必須(真偽)

以下を指定してはならない。

- 文字種
- 形式
- 必須
- 文字数(最小/最大)
- 数値(最小/最大)
- 正規表現

##### 数値
指定可能なValidationは以下とする。

- 必須
- 数値(最小/最大)

以下を指定してはならない。

- 文字種
- 形式
- 必須(真偽)
- 文字数(最小/最大)
- 正規表現

##### Enum
指定可能なValidationは以下とする。

- 必須

以下を指定してはならない。

- 文字種
- 形式
- 必須(真偽)
- 文字数(最小/最大)
- 数値(最小/最大)
- 正規表現

Enum値として許可される値の定義は、参照する列挙型設計書および自動生成Enumを正とする。画面設計書側で同じ候補値をValidationとして重複定義しない。

#### （９）Validation指定値
- 必須
  - `〇`：`Validators.required`生成対象
  - `-`：未指定
- 必須(真偽)
  - `〇`：`Validators.requiredTrue`生成対象
  - `-`：未指定
- 文字数(最小/最大)
  - `最小/最大`で指定する。
  - 最小のみ未指定の場合は `-/最大` とする。
  - 最大のみ未指定の場合は `最小/-` とする。
  - 両方未指定の場合は `-` とする。
- 数値(最小/最大)
  - `最小/最大`で指定する。
  - 最小のみ未指定の場合は `-/最大` とする。
  - 最大のみ未指定の場合は `最小/-` とする。
  - 両方未指定の場合は `-` とする。

#### （１０）ACG Validation仕様チェック
ACGはDTO生成前に、型・Enum型・文字種・Validation指定の組み合わせを検証する。

本設計書のValidationルールに反する指定が存在する場合、ACGは値を補正・無視して生成を継続してはならない。Exceptionを発生させ、コード生成を停止する。

例：

- `型=文字列`、`文字種=Unicode`、`形式=半角数字` → Exception
- `型=文字列`、`文字種=ASCII`、`数値(最小/最大)=0/100` → Exception
- `型=真偽`、`必須=〇` → Exception
- `型=数値`、`文字数(最小/最大)=1/3` → Exception
- `形式=正規表現`で`正規表現`列が未指定 → Exception
- `形式!=正規表現`で`正規表現`列が指定されている → Exception
- `型=Enum`で`Enum型`が未指定 → Exception
- `型!=Enum`で`Enum型`が指定されている → Exception
- `型=Enum`で文字種・形式・必須(真偽)・文字数・数値範囲・正規表現のいずれかが指定されている → Exception

Exceptionメッセージには、少なくとも以下を含める。

- 物理名
- 型
- Enum型
- 文字種
- 不正な指定項目
- 不正理由

例：

```text
画面設計書のDTO項目定義が不正です。
物理名: playerName
型: 文字列
Enum型: -
文字種: Unicode
不正項目: 形式=半角英数字
理由: Unicode指定時は形式チェックを指定できません。
```

ACGは不正な設計書を推測して補正しない。Fail Fastで生成を停止する。

#### （１１）ACG修正点
今回の画面設計書仕様変更に伴い、AlfredCodeGenerator（ACG）は以下を修正対象とする。

##### 画面設計書解析
- DTO項目定義の`Enum型`列を読み取れるようにする。
- DTO項目定義の`文字種`列を読み取れるようにする。
- `型=Enum`をDTO項目の型として解析できるようにする。
- `形式`に`半角英数字記号`を追加する。
- `文字数(最小/最大)`、`数値(最小/最大)`の`最小/最大`、`-/最大`、`最小/-`、`-`を解析できるようにする。

##### ACG内部モデル
- DTO項目モデルに`Enum型`を保持できる項目を追加する。
- DTO項目モデルに`文字種（ASCII / Unicode）`を保持できる項目を追加する。
- DTO項目の型として`Enum`を表現できるようにする。
- 既存の文字列・数値・真偽等の型とEnum型を混同しない。

##### Component DTO生成
- `型=Enum`の場合、`FormControl<指定Enum型>`を生成できるようにする。
- 指定されたEnum型のimportを生成する。
- Enumそのものは画面設計書から生成せず、既存の自動生成Enumを参照する。
- 同一Enum型を複数項目で使用する場合、importを重複生成しない。
- Enum型のFormControlは、コード値の文字列ではなくEnumオブジェクトを保持する。
- Enum型のデフォルト値を設定する場合、生成される初期値がFormControlのEnum型と型整合するようにする。
- デフォルト欄のコード値からEnum定数へどのように解決するかは、ACG実装修正時に既存Enum生成方式と照合して確定する。推測による変換は行わない。

##### Validation生成
- `文字列 + ASCII`の場合のみ、指定された形式に応じた文字種Validationを生成する。
- `文字列 + Unicode`の場合、Unicode専用の`Validators.pattern`は生成しない。
- `形式=半角数字`、`半角英数字`、`半角英数字記号`はACGが標準パターンを管理して生成する。
- `形式=正規表現`の場合のみ、`正規表現`列の値から`Validators.pattern`を生成する。
- `必須=〇`は`Validators.required`を生成する。
- `必須(真偽)=〇`は`Validators.requiredTrue`を生成する。
- `文字数(最小/最大)`は指定された側だけ`Validators.minLength` / `Validators.maxLength`を生成する。
- `数値(最小/最大)`は指定された側だけ`Validators.min` / `Validators.max`を生成する。
- `型=Enum`では文字種・形式・文字数・数値範囲・正規表現Validationを生成しない。

##### 仕様チェック（Fail Fast）
DTOコード生成前に、本設計書の型別Validationルールを検証する処理を追加する。

- `型=Enum`かつ`Enum型=-`はException。
- `型!=Enum`かつ`Enum型`指定ありはException。
- `型=Enum`で禁止Validation指定ありはException。
- `型=文字列`で`文字種`未指定はException。
- `型!=文字列`で`文字種`指定ありはException。
- `Unicode`で禁止Validation指定ありはException。
- `ASCII`で禁止Validation指定ありはException。
- `真偽`で`必須(真偽)`以外のValidation指定ありはException。
- `数値`で`必須`・`数値(最小/最大)`以外のValidation指定ありはException。
- `形式=正規表現`で正規表現未指定はException。
- `形式!=正規表現`で正規表現指定ありはException。
- 最小値が最大値を上回る等、最小/最大指定自体が矛盾する場合はException。

不正指定をACG側で補正・無視して生成を続行しない。

#### （１２）Enum FormControlの値取得・境界変換

Component DTO（UI Form DTO）のEnum項目は、FormControl内部にEnumオブジェクトを保持する。

例：

```ts
FormControl<AppCodeMatchTypeEnum>
```

この場合、FormControlから取得する値は以下の関係となる。

```text
matchType
  ↓ FormControl
matchType.value
  ↓ AppCodeMatchTypeEnum
matchType.value.value
  ↓ string（例："0" / "1"）
matchType.value.name
  ↓ string（例："SINGLES" / "DOUBLES"）
```

したがって、`matchType.value`で取得できるのはコード値ではなくEnumオブジェクトである。

Application DTO等が文字列コードを要求する場合は、画面ComponentのUI/Application境界でEnumの`value`を渡す。

例：

```ts
matchType: this.dto.formGroup.controls.matchType.value?.value
```

nullableでないことが型定義上保証されている場合は、optional chainingを使用せず以下でもよい。

```ts
matchType: this.dto.formGroup.controls.matchType.value.value
```

逆方向に、Application Response等の文字列コードをEnum型FormControlへ設定する場合は、対象Enumが提供する`toEnum()`等の既存変換処理を使用してEnumオブジェクトへ変換してから設定する。

```text
Application DTO / Response
string（例："0"）
  ↓ toEnum()
AppCodeMatchTypeEnum.SINGLES
  ↓ patchValue / setValue
FormControl<AppCodeMatchTypeEnum>
```

FormControlがすでにEnum型を保持しているUI内部では、値取得のたびに`toEnum()`を呼び出さない。

UI Form DTOとApplication DTO間のこの変換は画面Componentで明示的に行い、専用Mapperは作成しない。

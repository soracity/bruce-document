# 共通UI・計測・日付の実装補完

本章は02・05・13章の公開契約を実装するための内部設計である。追加の画面Input・新しい許容値・タップ寸法は設けない。原典で承認された規則と、ここで具体化したクラス・メソッド・CSS・解除手順を区別する。未決U-01／U-03は18章のままである。

## UIIMPL-01 共通スタイルを適用する手順

ComponentBaseの10 Input・10実効値・10 protected既定値メソッドは02章のとおり。次の内部計算を追加する。公開Inputを再宣言しない。

| メンバー | 型・引数・戻り値 | 処理 |
|---|---|---|
| assertInputs | protected、なし→void | 各booleanはundefinedまたはboolean、各数値はundefinedまたは許容集合、色はundefinedまたはAppUiColorEnum.values()の実体との同一性で検査。nullは既定値へ落とさずBRUCE_STYLE_VALUE |
| styleClasses | public ComputedSignal<string> | 以下の群ごとの固定クラスを空白結合。計算開始時にassertInputs。visibleはホスト側で別適用 |
| borderExplicit等 | protected boolean getter | 対応群のInputが1つでもundefined以外か。false／0もtrueとなる |
| backgroundForStyle | protected、なし→AppUiColorEnumまたはundefined | 通常はeffectiveBackgroundColor。CellではTABLE-03の色解決をoverride |
| textForStyle | protected、なし→AppUiColorEnumまたはundefined | 通常はeffectiveTextColor。CellではTABLE-03をoverride |
| backgroundClass | protected、色→string | 通常はgetBackgroundColorClass、CellだけgetTableCellStatusColorClass |

styleClassesの群：borderExplicitならgetBorderClass(effectiveBorder(),effectiveBorderWidth())、roundedExplicitならgetRoundedClass、shadowExplicitならgetShadowClass、padding明示ならgetPaddingClass。色は上記関数の返却色がundefinedでない場合に変換する。Buttonの既定SECONDARY・FABの既定PRIMARYは省略時も色を変換する。FABは省略時のshadow-lg／btn-circleを既存静的クラスで保持する。共通既定border=true等を、指定のないすべてのDOMへ強制する処理は書かない。

実体要素へ`data-bruce-style`と`[class]="styleClasses()"`を追加し、既存のDaisyUI基礎クラスを静的class属性へ残す。Angularが静的classとバインドclassを併合することをT-STYLE-11で確認する。利用画面が渡すclass文字列はこの計算へ一切入れない。visibleは通常UIのホストへ`[class.bruce-hidden]="!effectiveVisible()"`、Tableは28章の実体へ適用する。

### CSSの固定定義と優先順位

`src/styles/bruce-ui-overrides.css`をstyles.scssの共通定義から一度読み込む。次の定義はTailwind/DaisyUIのlayer外へ置き、数値はpxで固定する。共通クラスをグローバルに再定義せず、`[data-bruce-style]`付きの実体だけに限定する。Tailwindのテーマ設定やroot文字拡大で、指定した8pxが別値にならないようにする。padding未指定ならこれらのクラスを付けず既存テーマを保つ。

```css
.bruce-hidden { display:none !important; }
[data-bruce-style].border-0 { border-width:0; }
[data-bruce-style].border-\[0\.5px\] { border-width:0.5px; }
[data-bruce-style].border { border-width:1px; }
[data-bruce-style].border-2 { border-width:2px; }
[data-bruce-style].border-4 { border-width:4px; }
[data-bruce-style].rounded-none { border-radius:0; }
[data-bruce-style].rounded { border-radius:4px; }
[data-bruce-style].rounded-lg { border-radius:8px; }
[data-bruce-style].rounded-2xl { border-radius:16px; }
[data-bruce-style].rounded-3xl { border-radius:24px; }
[data-bruce-style].p-0 { padding:0; }
[data-bruce-style].p-1 { padding:4px; }
[data-bruce-style].p-2 { padding:8px; }
[data-bruce-style].p-3 { padding:12px; }
[data-bruce-style].p-4 { padding:16px; }
[data-bruce-style].p-6 { padding:24px; }
[data-bruce-style].p-8 { padding:32px; }
```

border群を明示する場合、上記に加えて`border-style:solid`、border-colorは既存の部品境界色を維持する。色は02章の22固定対応を同じ`[data-bruce-style].bg-*`／`.text-*`セレクターで明記し、値を各`var(--color-*)`にする。これは生成元の固定コードとして22行を記述する指示であり、実行時にクラス名を組み立てる指示ではない。20%の4クラスは`[data-bruce-style].bg-error\/20`等、CSSの`/`をescapeし、color-mix(in oklab,var(--color-error) 20%,transparent)を使う。sticky合成は28章のさらに限定したセレクターで上書きする。

shadow-sm/md/lgの値はアプリ固定依存のTailwindが生成する同名utilityを利用し、shadow=falseの明示時だけ`[data-bruce-style].shadow-none { box-shadow:none; }`を定義する。shadowサイズの独自数値や独自RGBを追加しない。borderWidthを変えても他群のpadding・色・影を消さない。クラスのHTML上の並び順を優先順位として扱わない。

## UIIMPL-02 FormControl基底の購読と派生クラスへの通知

02章STYLE-07へ次を補う。private currentControl:FormControl<T>またはundefined、private subscription:Subscriptionまたはundefinedを保持する。

| protectedフック | 引数→戻り値 | 基底の既定処理 |
|---|---|---|
| onControlBound | control:FormControl<T>またはundefined→void | 何もしない |
| onControlValue | value:T→void | 何もしない |
| onControlStatus | status:FormControlStatus→void | 何もしない |

Inputを読むeffectからbindControlを呼ぶ。参照同一ならreturn。旧subscriptionをunsubscribe→currentControlを更新→新Subscriptionを作成→valueChangesとstatusChangesを別々に登録→onControlBoundを呼ぶ→markForCheck。value通知はonControlValue→markForCheck、status通知はonControlStatus→markForCheck。effectはcontrol Inputだけを追跡し、フックの実行をuntrackedで包んでDateの表示Signal等を依存関係へ混入させない。

Dateはこれらのフックで表示・入力エラーを同期する。Textarea等の別部品は追加しない。必須部品はngOnInitとテンプレートからrequireControlを呼ぶ。Toggleは省略可。参照切替時にDateが付けたValidatorを旧controlから除去するのはDateの責務であり、他の購読やValidatorをclearしない。ngOnDestroyは自身の購読だけを解除する。DestroyRef.onDestroyへ同じ処理を登録する場合は二重呼出し可能な冪等関数にする。

## UIIMPL-03 測定の実体と変更通知

05章のLayoutMeasureUtilは次の型を持つ。

```ts
type MeasureTarget = { selector:string; mode:'intrinsic'|'native-input' };
// measure(element:HTMLElement):number
// measureContent(element:HTMLElement, targets:readonly MeasureTarget[]):number
```

measureContentは各対象の必要幅の最大を返す。横並びのRadio／Toggle／AlertではComponent自身が各要素幅＋現在の内部gapを合成し、完成した幅をserviceへ返す。配列が空ならhostのmeasureへ戻る。selectorが実体に一致しない場合はBRUCE_MEASURE_TARGETで構成エラーにし、0へ握り潰さない。非表示／未接続はLayout側で保留し、空の文字列の計測結果0とは区別する。

intrinsicは05章の接続済み複製をwidth:max-content／white-space:nowrapで測る。文字列とinputのvalue／placeholderはtextContentへ設定し、innerHTMLとして解釈しない。必要なcomputed styleはfont一式、line-height、letter-spacing、text-transform、box-sizing、padding四辺、border各辺、display、gapと列/行方向。元の割当済みwidth/min-width/max-widthはコピーしない。

native-inputは入力欄の現在の割当幅をそのまま読む方式にしない。Textboxはnative inputのsize属性（省略時はHTML既定）による自然幅を複製で測り、placeholder文字幅＋左右padding/borderとの最大を使う。Dateはtype/date UIを同じtypeで複製して自然幅を測る。inputの複製は元のFormControlやAngularへ接続せず、value/placeholder/type/sizeだけをコピーする。

Groupはlegend幅と子の必要幅を使う。内部にItemStackLayoutがある場合は行ごとの必要幅の最大、LayoutItemがある場合は子の必要幅とgapの合計を用いる。割当後の幅を必要幅として読み戻さない。TableContainerはwrapperの割当幅を上限にする内部scroll部品として扱い、scrollWidth全体を画面の必要最小幅へ押し付けない。

ComponentはafterNextRenderでregister(host,measureCallback)を実行し、返された解除関数をDestroyRefへ登録する。共通ライフサイクルの内部helper`watchMeasure(host,read,service,destroyRef):void`は、ResizeObserver(hostと表示対象)、MutationObserver(childList/subtree/characterData/class/style/hidden)、document.fonts.readyとloadingdoneを監視し、rAFを1件に集約してservice.invalidate(host)する。自身のmeasure cloneは監視対象外。破棄後のfonts.ready完了は何もしない。明示Signal Input変更・翻訳変更も同じinvalidateへ合流する。

LayoutItemはDOM childrenが変わるたびwatchの旧解除を呼び、新しい表示要素へ一度だけwatchする。ResizeObserverの旧要素もunobserveする。削除時／破棄時にLayoutが設定したflex/min-width/box-sizingを元のinline値へ戻す。LayoutSpanのflex-growと競合しないよう、Layoutは配分中flex shorthandを所有し、Directiveは重みCSS変数だけを変更する。初回fallbackに用いるgrowはそのCSS変数から取得し、Directiveが配分後のflex-basisを再上書きしない。

## UIIMPL-04 Dateの状態・エラー・編集フロー

Dateは二重のフォームを作らず、親controlに接続したまま表示文字列だけを内部Signalとして保持する。

| 状態／可視性 | 型／初期値 |
|---|---|
| public readonly displayValue | WritableSignal<string>、''。テンプレートから参照 |
| private draftError | WritableSignal<nullまたは{reason:string,raw:string}>、null |
| private attachedControl | FormControl<Nullable<string>>またはundefined |
| private inputValidator | ValidatorFn、インスタンスごとに1関数 |
| private syncing / selfWrite / destroyed | boolean、false |
| private originalUtc / originalInput | stringまたはundefined、未編集往復用 |

inputValidatorはdraftErrorがあれば`{dateInput:draftError()}`、なければnullを返す。DateがaddValidators(inputValidator)して所有し、解除時は同じ関数だけremoveValidatorsする。setErrorsで他Validatorの結果を保存し続ける方式は、次回のupdateValueAndValidityで消えるため採用しない。これはACGへ日付形式Validatorを生成する意味ではない。

onControlBoundは旧controlから関数を解除し、旧controlのupdateValueAndValidity({emitEvent:false})を実行。新controlへ追加し、現在値をcodecで検査・表示→updateValueAndValidity({emitEvent:false})。onControlValueはselfWrite中ならreturn、外部値ならdraftErrorを解除し同期。onControlStatusはdisabled状態を再描画するだけで、入力途中のdisplayValueを正しい旧値へ勝手に戻さない。

onInput(event)はtargetがHTMLInputElementか検査する。disabledならreturn。raw／native validityを取得しdisplayValueへ反映。validity.badInputがある場合は`incomplete`、その他の無効値は`invalidLocalValue`のdraftErrorを設定し、親の値は書き換えずmarkAsDirty→updateValueAndValidity({emitEvent:false})→markForCheck。raw=''かつbadInputなしは有効な未入力として''をsetValueしdirtyを更新する。形式変換成功ならdraftErrorを解除→selfWrite=true→setValue(変換値)→markAsDirty→finallyでselfWrite=false。自分の入力でdisplayValueを丸め直さない。onBlurでmarkAsTouched。

外部値が不正なら値を消さずdateInput.invalidStoredValueを返し、表示は''とする。外部値null／''は未入力でありDate自身はエラーにしない。requiredはACGの既存Validatorが判定する。日付・日時type切替は現在の値を新typeで再検査し、自動的に意味を変換しない。

### LocalDateTimeCodec

| メソッド | 引数→戻り値 |
|---|---|
| parseDate | raw:string→{year:number,month:number,day:number}または失敗理由 |
| toInput | value:Nullable<string>,type→{text:string,originalUtc?:string}または失敗理由 |
| fromInput | raw:string,type,original?:{utc:string,input:string}→{value:string}または失敗理由／U-03待ち |

DATEは`YYYY-MM-DD`（HTML入力が扱う正の年、4桁以上）を正規表現で成分分解。閏年は400で割れる、または4で割れ100では割れない年。月別日数で判定し、UTC Dateによるタイムゾーン変換は行わない。

DATE_TIMEの格納値は末尾ZのUTC ISO。`Date.parse`が有限、かつ年月日・時分秒をDateのUTC成分で往復検査して正規化による無効日を通さない。toInputはlocal成分から`YYYY-MM-DDTHH:mm:ss.SSS`を組み立てる。native inputは`step="any"`を付け秒・ミリ秒を保持する。これは文字入力の精度維持でありタップ寸法変更ではない。

fromInputは`YYYY-MM-DDTHH:mm`に任意の秒・1〜3桁の小数秒を認め、年/月/日/時/分/秒/ミリ秒を検査。秒省略=0、小数は右側0埋め。`new Date(0)`へsetFullYear(y,m-1,d)、setHours(h,m,s,ms)してローカル成分を往復比較し、違えばDST欠落等の`nonexistentLocalTime`。0〜99年をnew Date(y,...)の1900年補正へ渡さない。UTC保存はtoISOString。original.inputと現在rawの成分が同一で、originalUtcが有効なら元のUTCを保持する。DST重複する新規入力の選び方はU-03の選択を必要とする。

ngOnDestroyはinputValidator解除→基底購読解除→測定解除。disabledによって値・draftを消さず、非表示化をフォームresetの理由にしない。

## UIIMPL-05 Radio・Toggleの実体HTMLと操作順

Radioは13章のInputとReactive Forms接続を維持する。BUTTON型のlabelに独立したtabindex／role=radioを重ねず、native inputをフォーカス対象にする。二重のradio読み上げと、Spaceを処理できないlabelフォーカスを避ける。

```html
@if (type() === InputType.BUTTON) {
  <div class="join flex w-full">
    @for (option of values(); track option; let i = $index) {
      <label class="join-item btn flex-1 min-w-0 text-button font-button"
        data-bruce-style [class]="styleClasses()"
        [class.btn-active]="option === requireControl().value"
        [class.bg-secondary]="option === requireControl().value && backgroundColor() === undefined"
        [class.opacity-50]="requireControl().disabled">
        <input type="radio" class="sr-only" [name]="groupName()"
          [value]="option" [formControl]="requireControl()"
          [attr.aria-label]="optionLabel(i, option)" (change)="onChange()" />
        <span>{{ optionLabel(i, option) }}</span>
      </label>
    }
  </div>
} @else if (type() === InputType.RADIO) {
  <div class="join">
    @for (option of values(); track option; let i = $index) {
      <label class="bruce-radio-option">
        <input type="radio" class="radio" data-bruce-style [class]="styleClasses()"
          [name]="groupName()" [value]="option" [formControl]="requireControl()"
          [attr.aria-label]="optionLabel(i, option)" (change)="onChange()" />
        <span aria-hidden="true">{{ optionLabel(i, option) }}</span>
      </label>
    }
  </div>
}
```

optionLabel(i:number,option:T):stringはlabelKey[i]があれば既存i18nサービスで解決→label[i]があればその値→String(option)。同じキーの未解決時のフォールバックは既存i18n契約を使い、勝手に別言語へ固定しない。i18n変更でmarkForCheck／必要幅invalidateを行う。onChange():voidのOutputはAngularの値更新後であることをT-UI-03で検証する。値更新順を保証するため、同じchangeイベント内ではqueueMicrotaskへeventKeyのemitを1回予約し、その時点のcontrol更新後に通知する。予約時のeventKeyを保持し、destroy後はemitしない。独自setValueを重ねて2回valueChangesを出さない。

BUTTON型選択肢はflex:1、min-width:0。ラベルはwhite-space:normal／overflow-wrap:anywhere。`:focus-within`で既存のフォーカス輪郭を表示する。Radioの文字表示方式Inputは増やさず、Label/Button以外へのマーキーを勝手に広げない。

Toggleのネイティブ要素は次のとおり。13章のisChecked／isDisabledを使用し、checkedはboolean、controlはEnumのままとする。

```html
@if (type() === InputType.SLIDE) {
  <label class="label cursor-pointer">
    <input type="checkbox" class="toggle" data-bruce-style [class]="styleClasses()"
      [checked]="isChecked()" [disabled]="isDisabled()"
      [attr.aria-label]="resolvedLabel()" (change)="onChange($event)" (blur)="onBlur()" />
    <span aria-hidden="true">{{ resolvedLabel() }}</span>
  </label>
} @else if (type() === InputType.BUTTON) {
  <label class="btn btn-outline btn-secondary text-button font-button"
    data-bruce-style [class]="styleClasses()" [class.opacity-50]="isDisabled()">
    <input type="checkbox" class="sr-only" [checked]="isChecked()" [disabled]="isDisabled()"
      [attr.aria-label]="resolvedLabel()" (change)="onChange($event)" (blur)="onBlur()" />
    @if (icon()) { <span class="material-symbols-outlined" aria-hidden="true">{{ icon() }}</span> }
    <span aria-hidden="true">{{ resolvedLabel() }}</span>
  </label>
}
```

onBlur():voidはcontrolがあればmarkAsTouched。controlがなくchecked Inputだけを使う場合は親がtoggleChangeを受けて更新する。内部にダミーcontrolを作らない。type未指定の空表示も維持する。

## UIIMPL-06 Button・Label・Alert・Fab・Groupの残る内部契約

Label／ButtonはTextOverflowControllerをafterNextRenderで生成し、destroy時に破棄。翻訳後の文字列はviewportのaria-label／Buttonのaria-labelに一度だけ設定する。静止WRAPのtrackは`display:inline; white-space:inherit; overflow-wrap:inherit`、ELLIPSISのtrackはdisplay:inline、マーキーだけinline-block。inline-blockのままviewport側へellipsisを指定すると省略記号が出ないことがあるため、モードに応じ切り替える。

Labelのviewportは`role="img"`と全文aria-label、trackはaria-hidden。Buttonはnative buttonがアクセシブル名を持ち、viewportはaria-hidden。Labelへ未指定のpadding／枠／最小高さは加えない。Buttonは既存`.btn`寸法、WRAP時は文字を表示可能な高さへ自然に広がる既存レイアウトとの整合を試験し、独自の最低44px等を設けない。長文の収まりを理由にフォントを縮めない。

Alertは`levelClass():string`、`backgroundVariantClass():string`、`buttonVariantClass():string`、`icon():string`、`resolvedMessage():string`を持つ。INFO/SUCCESS/WARNING/ERRORは13章の固定クラス、アイコンは順にinfo/check_circle/warning/errorの既存Material Symbols。`alertButtonType=OK_ONLY`ならOKのみ、OK_CANCELならOKとCANCEL。各ボタンtype=button、(click)でonClick('OK'/'CANCEL')を呼ぶ。ボタン表示は現行互換のOK／CANCELを保持し、未定義のラベルキーを発明しない。通知キーもOK／CANCEL。SOFTボタン変換は既存互換のalert-softを保持し、新しいbtn-softへの変更をこの設計だけで承認済みにしない。

Groupはfieldsetへopacity-50だけを反映し、native disabled属性を付けない。withLabel=trueでのみlegendを描画。Fabは13章のsafe-area CSSと既存btn-circleを保持し、必要幅計測のため画面固定位置のボタンを通常行へ移動しない。

### 検証

T-STYLE-11：root fontを16px／20pxにし、padding=8・roundedSize=8・borderWidth=0.5の実測を比較し、明示値は8px／8px／0.5px。未指定は元DaisyUI表示。T-DATE-08：他Validator再実行後も不完全入力エラーが残り、Date破棄時には自分のValidatorだけ解除。T-UI-14：Radio変更のmicrotask後にcontrol.valueが更新済みでOutputが1回、破棄後0回。T-TEXT-09：ELLIPSISの実描画とスクリーンリーダー名に全文があること。これらはテスト仕様であり、本章作成時のAngular／実機合格を意味しない。


## UIIMPL-07 Alert・Group・Fabの全テンプレート

以下の固有InputはすべてSignal。enumButtonMsgはAppComponentInputTypeAlertButtonMsgTypeEnumへのreadonly参照。Alertはmessage用Pipe、Groupはlabel用Pipeをimportsへ登録する。ソース内Enumオブジェクトの文字列連結を固定変換へ置換する。

Alert：

```html
<div role="alert" class="alert alert-vertical md:alert-horizontal"
  data-bruce-style [class]="levelClass() + ' ' + backgroundVariantClass() + ' ' + styleClasses()">
  <div class="flex items-center">
    <span class="h-full material-symbols-outlined" aria-hidden="true">{{ icon() }}</span>
    <span class="h-full">{{ messageKey() ? (messageKey() | brf9018I18nMessage) : message() }}</span>
  </div>
  <div class="w-full md:w-2/3 md:ml-auto flex gap-2">
    <button type="button" class="btn text-button font-button btn-neutral flex-1 min-w-0 px-6"
      [class]="buttonVariantClass()" (click)="onClick('OK')">OK</button>
    @if (alertButtonType() === enumButtonMsg.OK_CANCEL) {
      <button type="button" class="btn text-button font-button btn-neutral flex-1 min-w-0 px-6"
        [class]="buttonVariantClass()" (click)="onClick('CANCEL')">CANCEL</button>
    }
  </div>
</div>
```

Group：

```html
<fieldset class="fieldset p-2 rounded-lg border ap-grid-border-color"
  data-bruce-style [class]="styleClasses()" [class.opacity-50]="disabled()">
  @if (withLabel()) {
    <legend class="fieldset-legend ml-2 pl-2 pr-2">
      {{ labelKey() ? (labelKey() | brf9018I18nLabel) : label() }}
    </legend>
  }
  <ng-content />
</fieldset>
```

Fab：

```html
<div class="fab">
  <button type="button" class="btn btn-primary btn-circle btn-lg shadow-lg"
    data-bruce-style [class]="styleClasses()" [attr.aria-label]="ariaLabel()" (click)="onClick()">
    <span class="text-2xl" aria-hidden="true"><ng-content /></span>
  </button>
</div>
```

全通常UIのhostに共通visibleを適用する。Textbox／Dateは13章のnative inputへdata-bruce-styleと[class]=styleClassesを追加する。Labelはviewport、Radio／Toggleは05節、Groupはfieldset、Fabはnative button、Alertはrole=alertのdiv。適用先をhostと内部に二重指定しない。未知Enum実体／許可外スタイルはBRUCE_STYLE_VALUEで停止し、任意CSS文字列へ連結しない。

## UIIMPL-08 グローバル表示の互換定義
